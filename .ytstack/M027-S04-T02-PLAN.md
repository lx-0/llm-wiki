## What this does

`process_request(request_path, dry_run=False)` real run becomes:

```
resolve candidate (existing) → folder_providers.get_provider()
  → provider.answer(topic, rationale, file_abs, file_rel)
  → sentinel/dispatch on the ScanAnswer:
      answer.error            -> RunResult(success=False, error)   [request untouched — T03 refines]
      "NOT ANSWERED IN THIS FILE" in answer_md
                              -> RunResult(success=False, "not_answered_in_file")
                                 [no artifact persisted — a non-answer is
                                  not a compile source; retarget/quarantine
                                  semantics are T03]
      else                    -> persist + flip request
```

Persist (`ANSWER_DIR = RAW_DIR / "notes" / "folder"`, mirror of email's
`DEEP_SCAN_DIR`): `answer-<slug>.md` where `<slug>` is lifted from the
request filename (`request-<slug>-<date>.json`, email-backend precedent).
Frontmatter (email deep-scan shape + S04 provenance per CONTEXT
reassessment): `type: note`, `kind: folder-deep-scan`, `topic`,
`root_id`, `file_path` (JSON-quoted, unmasked), `as_of_mtime` (from
ScanAnswer — the staleness tag this task's summary line demands),
`provider` (config value), `origin: "curiosity/folder-deep-scan"`,
`request_source`, `request_created`, `processed_at`. Body:
`# Folder scan — <topic>` + the provider's `answer_md` verbatim. The
file is a normal compile SOURCE (S01 option (a)) — compile distils it
on its next run; nothing writes `knowledge/` here.

Request flip on success: `status: "pending" → "processed"`,
`answer_path` + `processed_at` added (email-backend symmetry), written
back via json.dumps.

Tests (~4, extend the existing backend section; provider mocked at
`folder.get_provider` — call-time lookup, monkeypatch-able):

1. happy persist: fake provider returns distilled answer → answer file
   at `raw/notes/folder/answer-<slug>.md`, frontmatter carries
   `as_of_mtime` + `kind: folder-deep-scan`, body contains the answer;
   request JSON flipped to `processed` with `answer_path`.
2. **P2 sweep:** the fixture trove file contains a unique marker string;
   after a successful run, WALK every file under the tmp vault root and
   assert the marker appears NOWHERE (answer-only, no raw body).
3. sentinel: provider answers `NOT ANSWERED IN THIS FILE …` → no artifact
   under `raw/notes/folder/`, request stays `pending`, success=False.
4. provider error (`error="empty_result"`) → success=False, request
   untouched, no artifact.
