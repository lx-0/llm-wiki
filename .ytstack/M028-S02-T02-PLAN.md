# M028-S02-T02 -- Task Plan

**Summary:** Wire the deletion gate — `--allow-delete` flag + optional fact
`disposition: delete` field — into `apply()`, so the prompt's `${deletion_allowed}`
and the `_execute_deletes` executor are driven by real operator intent instead of
the hardcoded "false".

## Files

- Modify: `scripts/facts/correct_apply.py` — `_deletion_allowed(fm, flag)` helper;
  `apply(slug, dry_run, allow_delete=False)`; compute `deletion_allowed`, render
  with `"true"/"false"`, call `_execute_deletes(..., allowed=deletion_allowed)`;
  `main()` adds `--allow-delete`.
- Modify: `tests/test_correct_apply.py` — gate-resolution unit tests + an
  integration test (allow_delete=True end-to-end trashes a nominated file).

## What this does

`_deletion_allowed(fm, allow_delete_flag) -> bool` = `allow_delete_flag or
fm.get("disposition") == "delete"`. Either the CLI flag (per-run) or a fact-level
`disposition: delete` (per-fact, for facts that mark *factually false* content)
opens the gate. Default both absent → False → supersede.

`apply()` reads the fact frontmatter (already parsed as `fm`), computes
`deletion_allowed`, passes `"true"/"false"` to `render(..., deletion_allowed=…)`
(replacing S01's hardcoded "false"), and `_execute_deletes(actions, ROOT_DIR,
allowed=deletion_allowed)`. `main()` adds `--allow-delete` (default False) and
threads it to `apply`.

## Verification

```bash
uv run pytest tests/test_correct_apply.py -q && uv run pytest -q
```

Unit: `_deletion_allowed` true for flag / for `disposition: delete` / false for
neither. Integration: `apply(..., allow_delete=True)` with a mocked agent
nominating a deletion moves the file to `.trash/`; with the gate off it survives.
