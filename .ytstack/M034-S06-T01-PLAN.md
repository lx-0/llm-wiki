# M034-S06-T01 -- Task Plan

**Summary:** One table (exit criterion 4). Each catalogue command carries its own home-menu
entries. The TUI's quick actions, categories and fuzzy list are derived from `cli_catalog`,
and its hand-curated `QUICK_ACTIONS` / `CATEGORIES` literals are gone. A menu entry cannot
name a command outside the catalogue: its argv starts with the command it hangs off.
`core/actions`' rows, the GUI's pending work, are held to the same catalogue, without the
stale `BASH_OWNED_COMMANDS`. The non-TTY fallback prints `render_help()` in-process instead
of spawning `wiki help`.

  - `MenuItem(key, label, hint, args=(), prompt=None, special=None, quick=None)`.

## What this does

**One taxonomy: the catalogue's groups are the menu's categories.** These are differences
decided here, not drift:

| key | category | was |
| --- | --- | --- |
| `v` | Home & status (status, version) | under `g` setup |
| `g` | Setup | kept; backfill and usage moved out |
| `i` | Collect & ingest (collect, the OAuth aliases, produce, backfill, …) | `o` collectors + OAuth and `i` ingest merged |
| `k` | Knowledge ops (agent joins; compile `--all` browsable too) | kept |
| `d` | Facts & takes | kept |
| `r` | Review & maintenance (flush, curiosity, suggestions, triage, usage, …) | `a` automation |

- **Quick actions** are entries marked `quick=(key, footer label)`, with the same seven keys
  and labels: c, C, q, f, l, t, s.
- **The fuzzy list** holds each entry once; the `quick-*` duplicates go.
- **Key collisions:** h, x, digits and the quick keys stay taken. The new letters avoid them.
