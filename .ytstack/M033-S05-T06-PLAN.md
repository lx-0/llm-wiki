## What this does

**The fan-out.** The 80 files are split into eight shards of ten, read in parallel by
read-only subagents (Agent tool). Each item is re-derived from `scripts/`, `tests/`,
`CHANGELOG.md` and `git log`, ignoring what the file says about itself. Each verdict is one
of OPEN / PARTIAL / SHIPPED / SUPERSEDED / STALE_PREMISE, with the remaining work in one
sentence, the effort (S / M / L), and the evidence (paths, commits).

**The refutation.** Every SHIPPED / SUPERSEDED / STALE_PREMISE verdict goes to a second
subagent that tries to refute it: it looks for the code path, the test or the operator surface
that would still be missing. A verdict stands only if the refutation fails, because a wrong
SHIPPED deletes real work from the radar while an over-cautious OPEN costs nothing.

I read every verdict against its evidence before filing it; agent output is input, not truth
(CLAUDE.md § 6). Priority follows persona coverage and silent-failure risk, the rule in
CLAUDE.md and the 2026-08-27 cut.

Not a workflow: subagents through the Agent tool only, eight readers plus at most two
refuters.
