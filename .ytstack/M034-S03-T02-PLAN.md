# M034-S03-T02 -- Task Plan

**Summary:** Fix the hooks commands in the bash, then record them; release 0.7.16. The S03
oracle rule is fix first, record second, port third (T03). Three defects; the oracle
holds the wrong behaviour of two of them today:

1. **A payload that cannot be built** (S02-T05's end-to-end run). An agent's `jq` fails,
   the installer says `✗ unknown agent: claude`, writes nothing, and still ends
   `✓ Done. Restart agent CLIs…` with exit 0.
2. **`hooks uninstall` removes nothing from a current install** (the `hooks-uninstall`
   golden). Its filter matches `\.wiki/hooks/`, a drifted copy of the grammar: today's
   command is `cd '<vault>/.wiki' && uv run python hooks/…`. It backs the file up, leaves it
   as it was, and reports `✓ claude (user): removed wiki hooks`. And if jq fails on the file,
   `> tmp && mv` leaves a stray `.tmp` while still printing that line.
3. **Cursor's bare `{type, command}` entries.** The filter keeps only entries that carry a
   `.hooks` array, so an uninstall would drop the operator's other Cursor hooks too.

## Files

- Modify `lib/agents.sh`:
  - **One grammar.** `_WIKI_HOOK_CMD_RE` becomes T01's (the probe's union, with
    `_transcript`), and `hooks_installed`, the merge and the uninstall all use it.
  - **`install_one` names the failure.** "unknown agent" only for an agent the registry
    lacks. A payload that cannot be built gets
    `✗ <agent> (<scope>): could not build the hook payload — jq failed`.
  - **`merge_into_config` leaves no `.tmp`** behind when jq fails.
  - **`uninstall_one`** applies the one grammar to the decoded commands, in both entry
    shapes:
    - in `{matcher, hooks: […]}` groups it filters `.hooks`, and drops a group the removal
      emptied;
    - Cursor's bare entries stay unless they are ours;
    - an event array the removal emptied goes.
  - **Uninstall reports what happened:**
    - nothing ours in the file → `no wiki hooks in <cfg> — nothing to remove`, with no
      backup and no write;
    - invalid JSON → an error, the file untouched, no `.tmp`, return 1.
- Modify `lib/hooks.sh`: install and uninstall count failures. Any failure ends in
  `✗ <n> of <m> … failed — see above.` and return 1. `✓ Done` appears only when nothing
  failed. `setup` already passes its hooks child's exit code on (`setup_cli.py:29`).
- Modify `tests/test_hooks_merge.py`: direct bash tests of `uninstall_one`, written RED
  first:
  - today's commands are removed and another tool's group is kept (Claude);
  - Cursor's foreign bare entry is kept;
  - nothing ours → the file and its directory are untouched;
  - invalid JSON → return 1 and no `.tmp`.
- Modify `tests/test_bash_oracle.py`:
  - a behaviour test, written RED first: `wiki hooks install` with a `jq` that exits 126
    ends non-zero, names the failure and never says Done;
  - re-record `hooks-uninstall`;
  - new goldens: `hooks-uninstall-keeps-foreign` (Claude, user),
    `hooks-uninstall-cursor-keeps-foreign` (Cursor, project), `hooks-install-payload-fails`,
    `hooks-uninstall-nothing-to-remove`.
- Modify `CHANGELOG.md`, `pyproject.toml`, `uv.lock` (0.7.16).
