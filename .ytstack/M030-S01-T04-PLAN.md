# M030-S01-T04 -- Task Plan

**Summary:** Content-hash delta engine: transform the corpus into contract-shaped payloads, diff against the manifest, emit created/changed/deleted sets; a second run over unchanged input yields an empty plan (idempotency is the producer's job per contract).

## Files

- Create: `scripts/publish/delta.py`
- Create: `tests/test_publish_delta.py`

## What this does

- `ArticlePayload` (frozen dataclass): slug, rel, `name` (write_article arg — the pretty stem when `server_slug(stem) == slug`, else the slug itself, so the server-side re-slugification always reproduces OUR slug, disambiguated ones included), description, content (link-normalized body), `content_hash` = sha256 over name + description + content.
- `build_payloads(knowledge_dir, vault, slug_map, index)`: read each article, `normalize_links` body, `describe` description → payloads (sorted by slug).
- `plan_delta(payloads, manifest_articles) -> PublishPlan{create, update, retract, unchanged}`: slug missing from manifest → create; hash differs → update; equal → unchanged; manifest slug with no payload → retract (slug, rel).
- `record_published(store, payload)` / `record_retracted(store, slug)`: per-article manifest writes (`{"path", "hash"}`) via the locked StateStore — the S02 executor calls these only after server success.
