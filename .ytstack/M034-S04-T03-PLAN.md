# M034-S04-T03 -- Task Plan

**Summary:** The seed's special merges, pure, as T01's fixes left them. Each is held to its
bash function's output, recorded as goldens, and to a copy of the live vault's configs:
- the list union (`_merge_list_union`);
- the two button registries by id (`_merge_registry`, with the agent entries from
  `dashboard.agent_buttons` in-process);
- the `.env` example's stanza append (`_merge_env_example`).

The dashboard rewrite is Python already (`agent_buttons.update_dashboard` / `has_region`), so
T04 only calls it in-process.

## Files

- Modify: `scripts/core/jqjson.py`.
  - `unique`: jq's sort order (null < false < true < numbers < strings < arrays < objects;
    objects by their sorted keys, then the values), stable, so the first of equals stays.
  - `subtract`: jq's `a - b` by jq equality.
- Modify: `scripts/core/seed.py`, pure functions with no I/O and no messages (the messages
  are T04's).
  - `union_list(current, engine, key)` returns `(merged | None, adding)`. `key == ""` means
    the file is the list. A shape jq refuses raises `ShapeError`.
  - `merge_registry(config, key, engine_entries)` returns `(merged, added, updated)`, with the
    legacy object form read as the plugin migrates it, and `ShapeError` where jq errs.
  - `env_missing(template_text, current_text)` and `env_appended(template_text,
    current_text, missing)`. The awk stanza rule: the contiguous `#` block right above
    `KEY=`, and a blank line resets it. The `printf '\n\n%s\n'` append.
  - `engine_entries(template, kind)` for the registries: the template's entries plus
    `agent_buttons`' entries, in-process.
- Create: `tests/test_seed_merges.py` and `tests/golden/seed/merge-*.txt`.
  - The bash functions run on fixture files through a driver that sources `lib/seed.sh`, with
    `_agent_entries` stubbed to the same JSON Python gets.
  - Each golden holds the reported ids or keys and the file as written, or "(unchanged)".
    Python is held to it, and the bash half goes in T05.

## Cases

- **plugin-list:**
  - the template itself (nothing to add);
  - one engine plugin missing beside an own one;
  - an unsorted list that gets an addition (the union sorts);
  - duplicates;
  - not a list (shape).
- **snippet-list:**
  - an own snippet and a theme;
  - no `enabledCssSnippets` key (added at the end);
  - `enabledCssSnippets` not a list (shape).
- **button-templates / shell-commands:**
  - seeded from the template;
  - an own entry beside a stale engine one;
  - the plugin's own fields kept (`debounce`, migrated icons);
  - the legacy object form;
  - an entry without `id`;
  - a non-object entry (shape);
  - the key holding a string (the bash replaces it with the engine list; ported as is).
- **env:**
  - an engine var missing;
  - all present;
  - a commented `# KEY=` counts as present;
  - a var with no comment block;
  - a file without a trailing newline.
