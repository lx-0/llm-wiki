## What this does

```bash
_dispatch_python() {
  local venv="${UV_PROJECT_ENVIRONMENT:-$WIKI_DIR/.venv}"   # lib/common.sh's one rule
  case "$venv" in
    /*) ;;
    *) exec uv run --quiet --project "$WIKI_DIR" python "$WIKI_DIR/scripts/cli.py" "$@" ;;
  esac
  local stamp="$venv/.wiki-synced"
  if [[ ! -x "$venv/bin/python" || "$WIKI_DIR/uv.lock" -nt "$stamp" \
        || "$WIKI_DIR/pyproject.toml" -nt "$stamp" ]]; then
    uv sync --quiet --inexact --project "$WIKI_DIR"   # = uv run's implicit sync; set -e stops on failure
    touch "$stamp"
  fi
  export VIRTUAL_ENV="$venv" PATH="$venv/bin:$PATH"   # what uv run sets (measured in T03's follow-up)
  exec "$venv/bin/python" "$WIKI_DIR/scripts/cli.py" "$@"
}
```

- **Measured, not recalled.** `uv run` adds four variables. Two are reproduced: `PATH` (venv
  `bin/` first) and `VIRTUAL_ENV`. `UV` and `UV_RUN_RECURSION_DEPTH` have no reader in
  `scripts/`, `hooks/`, `lib/` or `desktop/src`.
- **`--inexact`.** `uv run` makes the minimum change and never removes extra packages from
  the venv; plain `uv sync` does remove them.
- **A failed sync fails the command.** Its error goes to stderr and the stamp is not written,
  as with a failing `uv run` today.
