# M034-S03-T06 -- Task Plan

**Summary:** Port `wiki skills install [--global|--no-global] / uninstall [--global] / sync /
status` to Python (`scripts/skills_cli.py`), at parity with the bash oracle. `wiki update`'s
post-pull step calls `wiki skills sync` through the entry: a not-yet-ported command calling
a ported one through its public interface, the S02 precedent. Release 0.7.19.

What moves:
- the engine-owned check (a symlink into `../../.wiki/skills/`);
- the local install, prune and uninstall;
- the global install for `GLOBAL_SKILLS` (absolute links in `~/.claude/skills/`, the
  vault registry at `${XDG_CONFIG_HOME:-~/.config}/llm-wiki/vaults`, writes failing soft);
- the `skills.global_install` flag: read fresh through `core.config`, written through its
  validated `set` path with stdout silenced (the bash's `config_set … >/dev/null`);
- the status table.

**Oracle first.** Six bash cases are recorded and pushed before the first line of port code.
They cover the branches the six existing cases do not reach:
- `skills-install-with-collision` — a foreign dir under the skill's name;
- `skills-sync-prunes-stale` — an engine-owned link whose skill is gone;
- `skills-status-mixed` — global on, linked locally, a stale link, the global link into
  another vault, the registry with this vault and a vanished one;
- `skills-status-collision` — foreign entries at both link paths, global off, no registry;
- `skills-uninstall` — an engine-owned link beside a foreign skill;
- `skills-install-no-global` — opted in, then `--no-global`.

Recording may find bash defects. Each is fixed in the bash first, then recorded.
