# M028-S01-T06 -- Task Plan

**Summary:** Golden integration test of the sandboxed apply pipeline over a
fixture vault with a mocked SDK — proves the engine annotates/renames but deletes
nothing. Surfaced + fixes a real T05 bug: an engine rename (Path.rename, unstaged)
shows as delete+create in snapshot/porcelain → `_divergence` false-fires. Make the
divergence check rename-aware.

## Files

- Modify: `scripts/facts/correct_apply.py` — `_execute_renames` returns the list
  of executed `{from,to}`; `_divergence(actions, delta, executed_renames)`
  reconciles raw deletions against engine-executed renames (basename-normalized)
  so a rename is not mistaken for a deletion; drop the unreliable rename-COUNT
  check (snapshot mode can't see renames). Wiring passes the executed list.
- Modify: `tests/test_correct_apply.py` — golden integration test (mocked
  `query` → proposal with a rename + zero deletions; assert file moved, wikilink
  rewritten, nothing deleted, fact stamped `applied`); a rename-does-not-false-
  warn test; update the 2 existing divergence unit tests to the new 3-arg signature.

## What this does

`_execute_renames` collects each successful `{from,to}` and returns the list.
`_divergence(actions, delta, executed_renames)`:
- `rename_froms = {basename(r["from"]) for r in executed_renames}`
- `real_deleted = {basename(d) for d in delta["deleted"]}` (porcelain rename `R`
  lines aren't in `deleted`; only unstaged-move `D` entries are — those are the
  rename froms, now explained)
- `declared_deleted = {basename(d) for d in actions["deleted"]}`
- `surprise = real_deleted - rename_froms - declared_deleted`
- warn if `surprise` — files vanished that neither a declared deletion nor an
  engine rename explains (the issue-#5 alarm, now false-positive-free on renames).

Golden test: tmp vault (knowledge/{projects,concepts}, facts/, index.md), a
