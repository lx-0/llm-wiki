## What this does

Adds an explicit lifecycle contract to the compile prompt. Without it, "State is rewritten each compile pass" means the LLM might lose unresolved Action Items between runs (catastrophic for a personal-task layer).

Rules:

1. **Read first, rewrite second.** Before rewriting an entity page's State block, Read the current file. Note all Action Items, Open Threads, and any manual `- [x]` checks.
2. **Carry forward unresolved.** Action Items that don't have resolution evidence in the new substrate stay in the rewritten State block, unchanged.
3. **Preserve manual `- [x]`.** Operator-checked items (`- [x]`) remain in State as-is, even on rewrite. Operator can manually move them to Timeline if they want; compile doesn't auto-demote `[x]` unless substrate evidence also indicates resolution.
4. **Deduplicate.** If the new substrate would produce an Action Item already in State (matched by task-phrase similarity), don't add a duplicate. Append a Timeline citation noting "re-mentioned on YYYY-MM-DD".
5. **Open Threads carry forward** the same way: keep unresolved blocked items unless the substrate resolves them.
6. **Stale-flag, don't auto-delete.** If a State item has no substrate evidence for 90+ days, append `[stale?]` annotation to its line instead of removing — operator triages.

Resolution-demotion logic is T02's job; T01 owns the carry-forward + preservation half.
