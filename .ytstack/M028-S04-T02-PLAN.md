# M028-S04-T02 -- Task Plan

**Summary:** `check_facts_violations` must not flag an article that is already
annotated as superseded BY this fact — it keeps the term in its historical body,
so without this it would be reported as a violation forever.

## Files
- Modify: `scripts/lint.py` — `_superseded_by_fact(art_fm, slug)` helper +
  read article frontmatter in `check_facts_violations`, skip the (article, fact)
  pair when the article is superseded by that fact.
- Modify: `tests/test_lint_facts_supersession.py` (new) — helper tests.

## What this does
`_superseded_by_fact(art_fm, slug)` = `art_fm.get("status") == "superseded"` and
the basename of `art_fm.get("superseded_by")` equals `slug`. In the per-article /
per-fact loop, `if _superseded_by_fact(art_fm, slug): continue` — the annotation is
the resolution, not a violation. An article superseded by fact A still gets flagged
for an unrelated fact B (the check is per-pair).

## Verification
```bash
uv run pytest tests/test_lint_facts_supersession.py -q && uv run pytest -q
```
Helper True for status superseded + matching superseded_by; False for a different
slug or a non-superseded article.
