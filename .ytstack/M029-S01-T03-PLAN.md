# M029-S01-T03 -- Task Plan

**Summary:** Expose `getListenerStatus()` to the renderer over IPC, typed
end-to-end (main → preload `contextBridge` → renderer). Closes S01: the app now
shows live listener status. All within `desktop/`.

## Files

- Create: `desktop/src/listeners/ipc.ts` — shared channel-name constant +
  `ListenerApi` type (the single contract both sides import — DRY, no string
  drift between main and preload).
- Create: `desktop/src/global.d.ts` — `declare global { interface Window {
  listeners: ListenerApi } }`.
- Modify: `desktop/src/main.ts` — `ipcMain.handle(LISTENER_STATUS_CHANNEL, ...)`
  returning `LISTENERS.map(getListenerStatus)`; log the result (dev-terminal-
  observable proof of the round-trip).
- Modify: `desktop/src/preload.ts` — `contextBridge.exposeInMainWorld('listeners',
  { status })` using `ipcRenderer.invoke`.
- Modify: `desktop/src/renderer.ts` + `desktop/index.html` — on load, call
  `window.listeners.status()` and render a minimal status line per listener.

## What this does

contextIsolation is on (scaffold default), so the renderer never touches Node —
it calls `window.listeners.status()`, which `invoke`s the main process, which runs
the T02 module and returns typed `ListenerStatus[]`. No bridge to the Python engine
(listener status is system data; see T02 re-scope). The renderer render is minimal
(text), real UI polish is S03.
