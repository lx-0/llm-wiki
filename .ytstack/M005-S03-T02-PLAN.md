## What this does

Adds explicit rules for the LLM's entity-lookup step:

1. **Slugification:** speaker name "Jane Doe" → slug `jane-doe`. Rule: lowercase, replace whitespace + non-alphanumerics with `-`, collapse runs of `-`, strip leading/trailing `-`. Examples: `Jane Doe` → `jane-doe`, `José García` → `jose-garcia` (drop accents to ASCII first), `Bob (CEO)` → `bob`.
2. **Lookup order:** Grep `knowledge/index.md` for the slug AND for the speaker's name as-typed. If neither hits, check the frontmatter `aliases:` of every existing `knowledge/people/*.md` for a case-insensitive match (the LLM can Grep `aliases:` across files).
3. **Disambiguation:** if two existing people pages match (e.g. two Janes), pick the one whose other Timeline entries share more attendees with the current meeting's attendee list. If still ambiguous, prefer the most recently `updated:` page.
4. **Stub-minimum shape when no match exists**, the LLM creates `knowledge/people/<slug>.md` with:
   - Frontmatter: `title`, `type: person`, `tags: [person]`, `compiled_from: [<this substrate path>]`, `created: ${today}`, `updated: ${today}`
   - One-line blockquote: `> First seen in <substrate path> on <YYYY-MM-DD>. <One-line note from context — role / company / project tie if mentioned, else just "no further context yet".>`
   - `## State` block with whatever fields the meeting reveals (often just `- **Role:** unknown` if nothing surfaced)
   - `## Action Items` containing the commitment that triggered the stub
   - `## Open Threads` empty
   - `## What they're building` empty body or single sentence
   - `## See also` empty
   - `---` + `## Timeline` with the substrate citation
5. **Don't stub for one-off mentions**: if the speaker appears in *exactly one line of dialogue* and that line is not a commitment (a passing reference, a "and Bob said hi"), DO NOT create a stub. Only commitments-by-speaker trigger stubbing.
