## What this does

Adds a new structural lint check. For every article whose `type:` is `person` or `project`:

1. **State block present** — file body contains a `## State` heading.
2. **Body separator present** — file contains a `---` separator line *after* the closing-frontmatter `---`. Detection: count of `^---$` lines must be ≥ 3 (two for frontmatter, one for the body separator) OR (≥ 2 AND a `## Timeline` appears below a `---` line).
3. **Timeline present** — file body contains a `## Timeline` heading.
4. **Timeline reverse-chronological** — Timeline entries that start with `- **YYYY-MM-DD**` are sorted newest-first. If two consecutive entries violate the order, emit a `timeline_not_reverse_chronological` warning naming the offending dates.
5. **Action Items syntax sanity** — if a `## Action Items` section exists, each non-empty line should start with `- [ ]` or `- [x]`. Anything else gets a `action_items_malformed` warning. (Full Obsidian-Tasks-syntax validation is T02's job; T01 only checks the bare `- [ ]/[x]` prefix.)

Severity: `error` for missing State / `---` / Timeline (structural breakage compile must not emit); `warning` for chronology violations and malformed action items. Severity `error` causes `wiki lint` to exit 1, matching the existing pattern.

Issue codes:
- `two_layer_missing_state`
- `two_layer_missing_body_separator`
- `two_layer_missing_timeline`
- `timeline_not_reverse_chronological`
- `action_items_malformed`
