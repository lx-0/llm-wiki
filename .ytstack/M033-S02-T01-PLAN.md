## What this does

Measured on `466f569`: 82 files carry a `sys.path.insert` in five shapes — `parent.parent`
(31, sub-package modules putting `scripts/` on the path to run as scripts), `parent` (19,
top-level scripts putting their own dir on the path, which Python already does for a script),
`parent.parent / "scripts"` (12, tests and hooks), `SCRIPTS_DIR` (7), `parents[3]` (6, the
reports engine putting `.wiki/` on the path for `scripts.`-prefixed imports). 28 files import
`scripts.core.*` / `scripts.reports.*` (75 lines: `study.py`, `analyze.py`,
`reports/_engine/**`, `tests/reports/**`, `tests/test_compile_role.py`); everything else
imports `core.*`. Probe 1: with both roots on the path, `core.paths is scripts.core.paths` is
**False** — two module objects, two `CONFIG`s, the KNOWLEDGE C01 trap — and `scripts` resolves
as an implicit namespace package (`__spec__.origin None`) because the directory has no
`__init__.py`. Probe 2: `runpy.run_module("collectors.cli")` from `scripts/` runs the
collectors CLI without any bootstrap. Cost: A rewrites 28 files' imports and deletes
bootstraps in 82; B rewrites imports in ~190 files *and* every operator hook command
(`python scripts/flush.py` no longer finds `scripts.core` without `.wiki/` on the path) —
M034's bash port, pulled forward. Decision: **A**. Consequences: one import identity
(`core.*`); `cli.py` spawns `[sys.executable, "-m", module, *args]` with `cwd=SCRIPTS_DIR`;
hyphenated scripts renamed; `sys.path.insert` only in `hooks/` (a shared bootstrap — hooks
are entry points Claude Code runs from anywhere) and pytest's `pythonpath` config; no
`scripts/__init__.py` (it would make `scripts.core` importable again from `.wiki/` and reopen
the split); a guard test in T04 pins all of it.
