# M028-S02-T03 -- Task Plan

**Summary:** Refuse a deletion-enabled run when the vault is non-git or has
uncommitted article changes, unless `--force`. A clean git tree is what makes
`.trash` + git recovery trustworthy.

## Files

- Modify: `scripts/facts/correct_apply.py` — `_tree_safe_for_deletion(vault)`
  helper; in `apply()` abort BEFORE spawning the agent when `deletion_allowed and
  not force and not safe`; `main()` adds `--force`, threaded to `apply`.
- Modify: `tests/test_correct_apply.py` — guard tests.

## What this does

`_tree_safe_for_deletion(vault) -> (bool, reason)`:
- not a git repo → `(False, "not a git repository …")`.
- `git status --porcelain -- knowledge ':(exclude)knowledge/facts'` non-empty →
  `(False, "knowledge/ has uncommitted changes …")`. The fact file (just created
  via `wiki correct add`) lives under `facts/` and is excluded — it's expected to
  be uncommitted.
- else `(True, "")`.

`apply(slug, dry_run, allow_delete=False, force=False)`: after computing
`deletion_allowed`, if `deletion_allowed and not force`: check the tree; on unsafe
`log.error(reason + "Re-run with --force to override.")` and `return 3` BEFORE the
agent spawns (don't pay for a run we'll refuse). Supersede-only runs are never
gated (non-destructive). `main()` adds `--force`.

## Verification

```bash
uv run pytest tests/test_correct_apply.py -q && uv run pytest -q
```

Tests: non-git → unsafe; clean git tree → safe; dirty article → unsafe (real
`git init` fixture); `apply(allow_delete=True)` on a non-git vault returns 3 and
never spawns the agent; `--force` bypasses.
