## What this does

`_print_request_card` branches on `r.get("type")`:

- `folder-deep-scan` card replaces the email-specific lines
  (Folder/Account/Source-quote) with:
  - `File` line: `<root_id>/<file_path>` + `(confidence N/5)`,
  - resolved absolute path via the same `watched_folders` lookup the
    backend uses (reuse `folder_backend._resolve`) + live
    `exists` / `MISSING — stale index?` marker (the operator sees
    staleness BEFORE approving),
  - the **consent line**, visually set off:
    `⚠ Accept will LOAD this file and send its content to <provider>`
    `  to answer: "<topic>"` — `<provider>` =
    `CONFIG.models.folder_scan_provider` (the operator learns exactly
    which backend sees the content; with a future local provider the
    same line honestly reads "local").
  - rationale block unchanged ("Why this file:" heading instead of
    "Why this folder:").
- email cards render byte-identically to today (regression-pinned).
- `_walk` itself is untouched — it already calls the card + dispatches
  on accept; the backend (T02-T04) does the rest.
