The hazard in every split is the tests' patch surface. A test that patches
`module.NAME` patches the module object it names; once the reader of `NAME` lives in
another module, the patch silently stops isolating and the test reads the real path. So
the rule for every group: the package / facade does NOT re-export a patched name — a stale
`monkeypatch.setattr(old, "NAME", …)` then raises `AttributeError` instead of passing on a
no-op — and every patch site moves to the module that reads the name. Measured surfaces:
`core.health` 13 names (`STATE_DIR` ×7, `_piggyback_tasks` ×5, `_failed_imports` ×4,
`WIKI_DIR` ×4, `ROOT_DIR`, `KNOWLEDGE_DIR`, `LOGS_DIR`, `STATE_FILE`,
`_FLUSH_LOG_TAIL_BYTES`, `_is_dataless`, `_effective_env_dir`, `_declared_import_names`,
`_ALL_CHECKS`); `lint` 1 (`_domain_tags` ×2); `cli` 3 (`_run_child`,
`refresh_dashboards`, `run_auth`, all staying with the dispatcher); `dream` 15 (twelve
path constants, `query`, `dream_entity`, `_maybe_web_research`); `gmeet` 6;
`sdk_helpers` 1 (`classify_failure`); `migrate_config_keys` 0.
