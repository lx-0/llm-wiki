# M030-S02-T06 -- Task Plan

**Summary:** OAuth user-token flow for the producer: one interactive browser consent mints access+refresh tokens (scope `offline_access`), persisted and headlessly refreshed — because write tools are user-principal only, the documented Keychain token is a read-only org key, and user JWTs are short-lived.

## Files

- Create: `scripts/publish/oauth.py`
- Modify: `scripts/publish/cli.py` (`--auth` flag; live path resolves token via the store, env `MEINKONTEXT_TOKEN` demoted to explicit override)
- Create: `tests/test_publish_oauth.py`
- Modify: `templates/.claude/.env.example` (correct the MEINKONTEXT_TOKEN entry: override/read-only role)
- Modify: `.ytstack/M030-CONTEXT.md` (token default decision corrected)

## What this does

- Discovery: `GET {origin}/.well-known/oauth-protected-resource/mcp` → authorization server → RFC 8414 metadata (path-insertion form first) → authorization/token/registration endpoints.
- `wiki publish --auth`: DCR (`token_endpoint_auth_method: "none"`, `grant_types: ["authorization_code","refresh_token"]`), PKCE S256, loopback listener on 127.0.0.1:<random>, authorize URL with `scope=offline_access` + `resource=<endpoint>` handed to the operator's browser, code exchange, tokens persisted at `STATE_DIR/meinkontext-oauth.json` (google_oauth token-cache convention, StateStore atomic).
- `current_access_token(...)`: valid access token → returned without network; expired → refresh-grant with rotation persisted; refresh failure → `PublishClientError` telling the operator to re-run `wiki publish --auth`.
- Token resolution order in the live path: OAuth store → `MEINKONTEXT_TOKEN` env (explicit override; write tools will reject org keys with the server's own guard text) → actionable error.
