## What this does

`make_path_scope_hook(allowed_write_roots, denied_subpaths=None)`:

- Resolve `denied_subpaths` to absolute paths once (alongside `resolved_roots`),
  default empty list when `None` → existing callers (compile/dream/folder
  provider) are byte-for-byte unchanged (backward compatible).
- In the hook, AFTER resolving the target path and BEFORE the allow-list loop:
  if `resolved` is under any `denied_subpaths` entry (`resolved.relative_to(d)`
  succeeds), return `permissionDecision: "deny"` with a reason naming the denied
  root. Deny takes precedence over allow.
- Then the existing allow-list loop runs unchanged.

In `correct_apply._apply_agent_options`, change the hook construction to
`make_path_scope_hook([KNOWLEDGE_DIR, DAILY_DIR, INDEX_FILE, LOG_FILE],
denied_subpaths=[FACTS_DIR])`. The agent can write across `knowledge/` (concepts,
projects, people, …), `daily/`, `index.md`, the operations log — but a write to
`knowledge/facts/<slug>.md` is denied at the hook, belt-and-suspenders to the
prompt's "never touch facts/" rule.

Pseudocode (hook core):

```python
resolved_denied = [Path(d).resolve() for d in (denied_subpaths or [])]
# ... inside hook, after `resolved = Path(raw_path).resolve()`:
for d in resolved_denied:
    try:
        resolved.relative_to(d)
        return _deny(f"{resolved} is under write-protected {d}")
    except ValueError:
        continue
# ... then the existing allow-list loop
```
