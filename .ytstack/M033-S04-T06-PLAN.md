## What this does

Each of the eleven reads as its section list; nothing a caller, a test, a request file, a
report, a state file, stdout or the logs can observe changes. The curiosity passes become
gates → candidates / folders → prompt → schema → one call → parse → per-gap write with the
drop ladder → the drop summary; the two SDK producers become gate → query → parse → write;
the renderers become frontmatter → sections → write; the CLIs become parser → validate →
dispatch per flag. Where two passes share a line (the drop summary) one helper renders the
identical text; where the wording differs (the two 404 hints) the lines stay where they
are. Moved verbatim, not fixed: `render_summary` numbers two sections "4." (per-instrument
radars and the frontmatter), `_persist_report`'s `engine_version: M019-S02-T04` stamp,
`run_inference`'s `print` reporting, `study.cmd_run`'s inline `import time as _time_mod` —
any of these is its own commit with its own test, not this task's.
