# M028-S04-T01 -- Task Plan

**Summary:** Make `supersession` a first-class fact status so `negation` stops
conflating *false* with *outdated*. A `supersession` fact annotates only — never
delete-eligible, even with `--allow-delete` / `disposition: delete`.

## Files
- Modify: `scripts/facts/correct.py` — `VALID_STATUS` += `"supersession"`; `--status` help.
- Modify: `scripts/facts/correct_apply.py` — `_deletion_allowed` returns False for
  `status == "supersession"` (the status itself forbids deletion).
- Modify: `tests/test_correct.py` + `tests/test_correct_apply.py` — tests.

## What this does
`supersession` = "was true, now outdated → annotate, never delete history" — the
clean home for M028's default behaviour, distinct from `negation` (a claim that may
be *false* and is the only delete-eligible status). `_deletion_allowed` short-
circuits to False when the fact's status is `supersession`, so neither the CLI flag
nor `disposition: delete` can open the gate on outdated-but-true content.
