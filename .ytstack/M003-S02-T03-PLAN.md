## What this does

The `wiki` script already has a `_refresh_dashboard_stats()` function (line 248-250) that runs `dashboard_stats.py` after every state-mutating subcommand. T01 wired `flush.py` to also refresh lint, but the shell wrapper paths (`wiki lint`, `wiki compile`, etc.) only refresh stats. This task makes the shell wrapper symmetrical: every subcommand that refreshes stats also refreshes lint.

Additionally, `cmd_seed` currently doesn't refresh either cache. After a fresh install, the operator would have to run `wiki flush` once before the Dashboard shows real numbers. Adding both refreshes to `cmd_seed` end means `wiki seed` produces an immediately-usable Dashboard.

Helper:
```bash
_refresh_dashboard_lint() {
  uv run --quiet --project "$WIKI_DIR" python "$WIKI_DIR/scripts/dashboard_lint.py" 2>/dev/null || true
}
```

(Note: this preserves the existing silent-failure pattern for now. S07-T03 will tighten it across the board — for this task, parity with `_refresh_dashboard_stats` is the rule.)
