# M025-S01-T03 -- Task Plan

**Summary:** Deterministic `state/capture_index.json` mapping
`capture_id → {source_path, created, status: "open"}`, written at ingest by the
capture collector. The bridge S02 (forward link) and S03 (supersede) both
consume. Idempotent on re-ingest — a re-drop of identical content (same
capture-ID) never resets an entry, so an S03-set `status: superseded` survives.

## What this does

`core/capture_index.py` mirrors the `core/usage.py` flock pattern + the
`core.utils.load_json_state/save_json_state` helpers:

```python
CAPTURE_INDEX_FILE = STATE_DIR / "capture_index.json"
_LOCK_FILE         = STATE_DIR / "capture_index.lock"
STATUS_OPEN, STATUS_SUPERSEDED = "open", "superseded"

@contextmanager
def _locked(): ...  # fcntl.LOCK_EX on _LOCK_FILE, mkdir parents

def load() -> dict[str, dict]:
    # load_json_state; on ValueError/OSError (corrupt/partial) → {} (never
    # crash the ingest path; next record() rewrites cleanly)

def record(capture_id, *, source_path, created) -> bool:
    with _locked():
        index = load()
        if capture_id in index:
            return False                      # idempotent: preserve existing
        index[capture_id] = {"source_path": source_path,
                             "created": created, "status": STATUS_OPEN}
        save_json_state(CAPTURE_INDEX_FILE, index)
        return True
```

`source_path` is the canonical raw article (`raw/captures/capture-<id>.md`)
relative to ROOT_DIR — the path both consumers resolve from the ID. `status`
starts `open`; S03 will flip it to `superseded`; the next compile cycle honours
it. Idempotent re-record (return False, entry untouched) is exactly what makes a
re-ingest non-destructive to a correction already recorded.
