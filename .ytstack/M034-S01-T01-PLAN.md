# M034-S01-T01 -- Task Plan

**Summary:** Bash oracle, read-only commands. A fixture vault plus a fixture `HOME`; the real
bash `wiki` runs under them, and the normalised stdout / stderr / exit code are recorded as
goldens. Covered: `help`, the bash help texts, `version`, `status`, `menu` with no TTY,
`doctor --quick --json`, `config get/keys/path/status`, `hooks status`, `skills status`, and
the `dream` / `dream-entity --help` routing. The task extends `tests/_oracle.py` and does not
fork it.

## Files

- Modify: `tests/_oracle.py`
  - `assert_matches_golden` / `diff_against_golden` take a `golden_dir` (default unchanged).
  - New: `build_engine_copy(vault)`, `uv_shim(bin_dir)`, `run_wiki(vault, home, *args)` and
    `normalise_text(text, placeholders)`.
- Create: `tests/test_bash_oracle.py` — one parametrized test per read-only command, each
  compared against `tests/golden/bash/<name>.txt`.
- Create: `tests/golden/bash/*.txt` — recorded from the bash version with
  `--snapshot-update`, committed in the same commit as the harness.

## What this does

**The engine copy.**
- `<fixture>/.wiki/` receives copies (not symlinks) of `wiki`, `lib/`, `scripts/`, `hooks/`,
  `skills/`, `templates/`, `config.example.yaml`, `pyproject.toml` and `uv.lock`.
- Copies, because `core/paths.py` resolves its own file. A symlinked `scripts/` would make
  `ROOT_DIR` the repo's parent instead of the fixture vault.
- The copy is `git init`-ed with one commit, a fixed author / date and a fixed
  `remote.origin.url`, so `wiki version` has a checkout to report. Revision hashes are
  normalised to `<REV>`.

**The vault.**
- `build_fixture_vault` (the M033 oracle's) builds the vault, with `.obsidian/` for the vault
  guard.
- `.wiki/config.yaml` is seeded from `config.example.yaml`, with `models.ollama_url`
  pointed at a closed local port so the doctor's probe fails fast and deterministically.

**`uv`.**
- A shim first on PATH drops `run [--quiet] [--project X]` and execs the repo venv's Python
  with the remaining argv (`PYTHONPATH` is passed through as the bash set it).
- So no test run syncs or mutates any venv, and the bash → Python hop is the one the bash
  makes.

**`HOME`.**
- A fixture dir with empty agent config dirs, so `hooks status` / `skills status` see a
  machine with nothing installed — deterministic, and never the real `~`.
- `PATH` is pinned to the shim + `/usr/bin:/bin` + the venv's bin. `TERM` is unset and stdin
  is `/dev/null`, so there is no TTY and no colour.

**Normalisation.** The vault path → `<VAULT>`, `HOME` → `<HOME>`, the repo venv path →
`<VENV>`, hex revisions → `<REV>`, ISO timestamps → `<TS>`, durations / ages → `N`. Only
what is volatile; each rule is named in the golden's header line.

**What is recorded.** Per command, `$ wiki <args>` then `exit: <code>`, then `--- stdout ---`
and `--- stderr ---`. The goldens are the bash version's behaviour, to which S01-T05 and the
S02–S05 ports must stay byte-identical (or decide a difference in their commit).

## Verification

```bash
uv run --frozen pytest tests/test_bash_oracle.py -q    # green without --snapshot-update, after the goldens are recorded
uv run --frozen pytest -q                              # full suite green
```

A guard must be seen to fail: change one character in a bash help text in the fixture copy
→ the test names the diff; restore. Success: both commands exit 0, and the goldens show the
bash output a reviewer can read. Failure: re-read the plan and check whether the spec drifted.
