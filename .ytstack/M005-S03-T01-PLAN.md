## What this does

Adds a new compile-prompt section: **"Extracting commitments from meeting substrates."** When the `${source_path}` matches `raw/transcripts/jamie/` or `raw/transcripts/gmeet/`, the LLM is instructed to:

1. **Identify commitments** in the transcript: explicit phrases like "I'll send X by Y", "Jane will follow up on Z", "we agreed to ship A on B", "decided we wait for C". Each commitment is a quartet:
   - **Task** — what gets done (verb phrase)
   - **Owner** — who owns it (speaker name → entity wikilink)
   - **Deadline** — when, if mentioned (mapped to `📅 YYYY-MM-DD`); omit if unstated
   - **Context** — one-line substrate citation

2. **Route to the right entity page**:
   - If the Owner is a known person (matches an existing `knowledge/people/<slug>.md` entry), update that page's `## Action Items` section
   - If the Owner is the operator (first-person commitments — "I'll send the deck"), the action item also lands on the related project page's `## Action Items` if a project is mentioned
   - If a commitment depends on someone else's action ("waiting for Bob's approval"), it goes into the Owner's `## Open Threads` not Action Items
   - If no matching entity page exists, create one (via the two-layer template from Instruction 3)

3. **Cite the substrate in Timeline**: every entity page touched in step 2 gets a new Timeline entry of the form `- **YYYY-MM-DD** | \`raw/transcripts/jamie/...md\` — short note on what happened in this meeting.`

4. **Don't extract what's not a commitment**: idle mentions, references, gossip — skip. Quality > recall. Better to miss a fuzzy commitment than fabricate one.

This is the **schema rule**; T02 deepens entity-resolution (existing-entity match + create-stub fallback), T03 is routing-correctness inside `compile.py`, T04 is a fixture test, T05 is the real-substrate canary.
