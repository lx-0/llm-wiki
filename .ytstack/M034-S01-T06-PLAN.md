## What this does

`run_command` resolves routes in this order:
1. **Help.** `-h` / `--help` / `help` prints the help text.
2. **A route named by the first argument.** Its key is consumed and its `args` go first.
3. **The default route.** Taken when there are no arguments, or the first one starts with
   `-`. Nothing is consumed, and the route's `args` go first.
4. **A refused word.** With `takes_args=False`, an unrouted word gets the dispatcher's
   "unknown" message and exit 1.
5. **The default handler,** with `handler_args` first. A bare command shows its help when
   `show_help_on_empty` is set.

**The one decided difference** is the `dream bogus` message. Bash printed `✗ unknown: wiki
dream bogus (try 'wiki dream help')`; the dispatcher prints `wiki: unknown: wiki dream bogus
(try 'wiki dream help')`. That is the same text after the prefix, and the same exit code 1,
matching `menu bogus` since T05.
