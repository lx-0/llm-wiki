## What this does

`dashboard_lint.py` is a sibling to `dashboard_stats.py` — same import pattern, same output shape (vault-root MD file with frontmatter + body), same caller contract (run via `subprocess` from `flush.py`, also runnable standalone with `--dry-run`).

**Imports + counters.** From `scripts.lint` import the three structural-only check functions:
- `check_orphan_pages()` — articles with no inbound links from index/MOCs
- `check_stale_articles()` — articles with mtime older than threshold
- `check_missing_backlinks()` — articles whose links don't backlink correctly

These return `list[Issue]` (or whatever lint.py's existing shape is — verify at impl-time by reading lint.py output for one of these functions). The fourth queue is filesystem-only:
- `failed_flushes` — enumerate `SESSIONS_DIR / "failed-flushes" / "*.md"` (FAILED_DIR pattern from dashboard_stats.py:46)

**Output file.** `OUTPUT_FILE = ROOT_DIR / "_dashboard-lint.md"`. Format:

```markdown
---
orphans_count: 12
stale_count: 47
missing_backlinks_count: 3
failed_flushes_count: 1
last_updated_ts: 2026-05-02T22:15:00+02:00
---

## Orphans

- [[knowledge/concepts/foo]] — never linked from index
- [[knowledge/projects/bar]] — never linked from index
- ...

## Stale

- [[knowledge/concepts/baz]] — last touched 2026-02-14 (78d ago)
- ...

## Missing backlinks

- [[knowledge/foo]] — links [[bar]] but [[bar]] doesn't link back
- ...

## Failed flushes

- `scripts/sessions/failed-flushes/2026-04-29T1812.md` — error: `<short-snippet-from-file>`
- ...
```

Each section: one line per issue, format `- [[wikilink]] — <short detail>`. Detail is whatever the corresponding `Issue.detail` field contains (truncate at ~120 chars).

**Empty queues.** If a check returns `[]`, render the section header anyway with no body lines (so the Dashboard's `![[_dashboard-lint#Section]]` embed has a valid target — even if empty, the embed must resolve).

**Defensive try/except per check.** Same pattern as `dashboard_stats.py:count_lint_warnings()` (lines 100-105) — wrap each check in try/except and log a warning if it crashes; do not let one broken check kill the whole script.

**Hook into flush.py.** Mirror the `refresh_dashboard_stats()` pattern, but apply the S07 stderr-not-DEVNULL fix preemptively here so we don't ship a new silent-failure path:

```python
def refresh_dashboard_lint() -> None:
    """Regenerate `_dashboard-lint.md` so the vault Dashboard reflects the
    lint queues after this flush. Synchronous and best-effort."""
    try:
        result = subprocess.run(
            [sys.executable, str(DASHBOARD_LINT_SCRIPT)],
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            stdin=subprocess.DEVNULL,
            check=False,
            timeout=30,
        )
        if result.returncode != 0:
            log.warning(
                "dashboard_lint refresh failed (exit=%d): %s",
                result.returncode,
                result.stderr.decode("utf-8", errors="replace")[:500],
            )
    except Exception:
        log.exception("Failed to refresh dashboard lint")
```
