## What this does

`piggybacks.capture` becomes an operator-overridable knob (enabled / cooldown),
matching every other Registry collector (voice, pictures, jamie, gmeet,
calendar) which all carry an entry in `_default_piggybacks()` even though
`flush.py:_build_piggyback_tasks()` auto-discovers them from the Registry. Without
the entry, `flush.py` falls back to the SPEC cooldown (still works) but the
operator has no migrated knob to disable/tune the capture piggyback.

- `config.py`: `_default_piggybacks()` gains `"capture": PiggybackTask(cooldown_hours=1)`.
- `migrate_config_keys.py`: existing operator vaults at `<vault>/.wiki/config.yaml`
  get `piggybacks.capture: {enabled: true, cooldown_hours: 1}` written in on next
  `wiki update` (dataclass default fall-through is NOT operator-visible — the
  migration is the only legal write path).
- `config.example.yaml`: documents both the `personal.capture_inbox` folder knob
  (one-tap quick-capture inbox) and the `piggybacks.capture` cadence block, in the
  same prose style as `voice` / `pictures`.
- Docs (`templates/AGENTS.example.md` + `AGENTS.md`): `raw/captures/capture-<id>.md`
  (collectors/capture_collector.py — folder-watch on `personal.capture_inbox`,
  content-hash capture-ID, idempotent re-drop, two-zone archive under
  `raw/inbox-mobile/captures/`) added to the substrate tree; `captures.md` added
  to the `daily/<date>/<source>.md` writer list.

Out of scope (follow-up, NOT this task): `docs/setup-capture.md` operator setup
recipe (separate doc genre, not in the slice plan — mirror setup-voice.md when
the loop is operator-facing). Logged as an S01 follow-up.
