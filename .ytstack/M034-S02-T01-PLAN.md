# M034-S02-T01 -- Task Plan

**Summary:** Line-based prompt helpers on `core/console`, next to `read_key`: `confirm`,
`ask`, `select_one`, `select_many` and `pause`. They are the Python counterpart of `lib/ui.sh`
that the S02 / S03 / S05 ports use. Open question 3 is decided in DECISIONS, on measurements
rather than recall.

## Files

- Modify: `scripts/core/console.py`. Five helpers, plus `read_line(fd=0)`, which reads byte by
  byte (`os.read(fd, 1)`) up to `\n` and returns `None` at EOF with nothing read.
- Create: `tests/test_console_prompts.py`, with answers scripted through an `os.pipe()`.
- Modify: `.ytstack/DECISIONS.md` — the open-question-3 entry. `.ytstack/M034-CONTEXT.md` — the
  question is closed.

## What this does

Semantics, from `lib/ui.sh`:

| Helper | Returns | Rules |
| --- | --- | --- |
| `confirm(prompt, default=True)` | `bool` | Hint `[Y/n]` / `[y/N]`; an empty line or EOF takes the default; a leading `y Y j J` is yes (German *ja*) |
| `ask(prompt, default="", validate=None)` | `str` | Hint `[default]` when there is one; an empty line or EOF takes the default; a `validate` that returns False asks again |
| `select_one(prompt, options, default=1)` | the option string | Numbered list, `*` on the default; anything not a number in range takes the default |
| `select_many(prompt, options, defaults)` | `list[str]` | Space-separated numbers; empty → the defaults; out-of-range and non-numeric tokens are skipped (the T02 fix's semantics) |
| `pause(text="Press Enter to continue")` | — | reads one line |

- **Everything prompt-like goes to stderr, `confirm` and `pause` included.** That is a
  decided difference: in bash those two printed to stdout. Stdout is the value, stderr the
  UX, so a captured or piped `wiki setup` keeps stdout clean. The goldens move only when a
  port wires the helpers in (S02-T02 / T03), and that commit says so.
- **Colours** use `core/console`'s stderr-gated `C_*`.
- **EOF never loops.** A validator that rejects EOF's default returns the default instead of
  re-asking forever, because no input means no further answer will come.

**Open question 3 is decided on measurements** (`/tmp/m034-oss-probe`, 2026-10-15). With two
answers piped on stdin:
- `questionary.confirm` returned the right value, but warned `Input is not a terminal (fd=0)`
  on stderr, wrote a terminal redraw (`\r\n` ×7, padding, a repainted line) to stdout, and
  consumed **all** remaining stdin (`REST ''`);
- `prompt_toolkit.prompt` did the same three things;
- plain Python `sys.stdin.readline()`, followed by a child `sh -c 'read -r x'`, left the child
  with nothing, because Python had read ahead.

The dependency cost is *not* the reason; the recommendation's wording was wrong.
`prompt_toolkit` is already in every vault (`menu.py`), and questionary is small. The reasons
are pipe behaviour, stdout cleanliness and parity with the bash prompts.
