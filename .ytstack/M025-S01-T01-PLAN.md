# M025-S01-T01 -- Task Plan

assigns a deterministic, re-drop-idempotent capture-ID to each capture, writes a
frontmatter-stamped note to `raw/captures/`, and two-zone-archives the source.

## What this does

`capture_collector.py`, structured like `voice.py`:

- `SPEC = CollectorSpec(name="capture", output_subfolder="raw/captures",
  piggyback_default=True, piggyback_cooldown_hours=…, supports_incremental=False,
  supports_account_loop=False)`. (Cooldown value + the operator-override knob land
  in T02; the SPEC default lives here.)
- `_inbox_path()` reads `CONFIG.personal.capture_inbox` (expanduser), returns None if
  empty -- same shape as voice's `_inbox_path`.
- `is_configured()` -> inbox set AND exists.
- `_capture_id(content)` -> deterministic ID = first 12 hex of
  `sha256(content.strip().encode("utf-8"))`. Same content ⇒ same ID (idempotent on
  re-drop); edited content ⇒ new ID (correctly a new capture). Collision across two
  genuinely-distinct captures with identical text is accepted for v1 (note it).
- For each eligible source (`.txt`/`.md`/`.html`, via a `_scan_inbox` like voice's):
  read text (utf-8, skip empty → archive without ingest like voice), compute
  `capture_id`, build frontmatter, write to `raw/captures/capture-<id12>.md`.
  **Filename is ID-derived, so a re-drop overwrites the same file (idempotent) rather
  than spawning a duplicate** -- this is the key divergence from voice's timestamp+slug
  naming. Body = capture content verbatim (NO punctuation pass -- captures may be
  article snippets; keep raw).
- Frontmatter:
  ```
  ---
  type: capture
  origin: capture-intake
  capture_id: <id12>
  captured_at: <iso, from src mtime in TIMEZONE>
  source: <src.name>
  tags: [capture]
  ---
  ```
- Two-zone archive: `shutil.move` source → `raw/inbox-mobile/captures/` (mirror voice's
  `MOBILE_ARCHIVE_DIR`; collision → suffix with mtime, same as voice).
- `_append_daily_rollup(...)` → `daily_capture.append(date_iso, "captures", line)`,
  swallow failures (side-effect, never break primary write). NOTE: `daily_capture`
  may carry a `KNOWN_SOURCES` allow-list (the pictures collector needed it extended,
  per project memory) -- if `"captures"` isn't accepted, extend it here; verify the
  rollup line actually lands.
- `@register` so the Registry discovers it.

State/index (`state/capture_index.json`) is **T03**, not here. Piggyback override
knob + `config.example.yaml` docs + `templates/` sync are **T02**.

## Verification

```bash
uv run --project .wiki pytest tests/test_capture_collector.py -q
```

Tests must cover: (1) `_capture_id` determinism + idempotency (same content → same
id; different content → different id); (2) a dropped `.md` produces
`raw/captures/capture-<id>.md` with the expected frontmatter (capture_id, type:
capture); (3) re-dropping the SAME content overwrites, does not duplicate; (4) the
source is moved into `raw/inbox-mobile/captures/`; (5) empty file is archived without
an artifact. Use a tmp inbox + monkeypatched `RAW_DIR` / `CONFIG.personal.capture_inbox`
(see how `tests/` set up voice/pictures collectors).

Success: command exits 0, all assertions pass. Failure: re-read plan, check if spec drifted.
