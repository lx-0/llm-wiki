## What this does

The rule set is the audit's (`deslop-arc.md` §3.1). Rules whose findings are style opinions
the engine has deliberately taken the other side of are ignored *with the reason in the
config*: PLC0415 (999 — lazy imports inside functions are the engine's startup-time and
cycle-avoidance pattern, KNOWLEDGE "lazy-import CLI module"), PLR2004 (511 magic values —
the thresholds that matter are config knobs already; the rest are formats and offsets),
E501 (200 — the formatter owns line length; what is left is strings and comments it cannot
wrap), RUF001/002/003 (165 — the en-dashes, arrows and ellipses in strings, comments and
docstrings are typography, not typos), and the complexity family C901 / PLR0911 / PLR0912 /
PLR0913 / PLR0915 / PLR0917 (~260 — S04 gates function *length* with a committed AST test;
complexity thresholds are revisited at the S04 close, not before). `per-file-ignores`: F401
in `__init__.py` (re-exports) and E402 in the entry scripts that `sys.path.insert` before
their imports (S02 removes the bootstrap, then the ignore). Then one `ruff check --fix` run
applies the safe fixes — unused `noqa` removed, imports sorted (`known-first-party` set so
`core`, `collectors`, `facts`, … sort as first-party), `timezone.utc` → `datetime.UTC`,
unused imports dropped, deprecated typing imports modernised, placeholder-less f-strings and
manual `import x.y as y` cleaned — followed by `ruff format` (fixes can leave whitespace the
formatter wants back). What remains after this task is the hand-fix residue T04 owns
(PLW1510, RUF059, N806, RUF012, E702, E741, SIM105/117, PLW2901, F841, …); the task records
that count. The suite and the behaviour oracle prove nothing changed.
