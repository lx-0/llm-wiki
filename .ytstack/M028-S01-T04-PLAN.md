## What this does

`_parse_proposed_actions(text)`: run `parse_json_lenient` (strips fences, falls
back to outermost `{...}`) over the agent's result text; coerce to a dict with the
four keys, each defaulting to `[]`; **shape-guard** every value with
`isinstance(x, list)` (LLM output lies about types — CLAUDE.md). `renamed` entries
that aren't `{"from","to"}` dicts are dropped.

`rename_article(old, new, knowledge_dir, vault)`:
1. Before moving (resolution needs the file present), walk knowledge articles +
   `index.md`; for each live wikilink, `resolve_link(target, source, vault)`; if it
   resolves to `old`, rewrite to `relative_target(new, source, has_ext)`.
   Collect per-source new text.
2. `old.rename(new)` (mkdir parents).
3. Write the collected rewrites (the moved file's own row maps to `new`).
Cross-dir moves leave the moved file's *outgoing* links stale-relative — the
compile-time `run_relativize_pass` + `wiki links` audit already fix that; note it.

`_execute_renames`: for each `{from,to}` in `actions["renamed"]`, resolve to vault
paths under `knowledge/`, call `rename_article`, log each. Guard: skip if `from`
missing or `to` already exists.

In `apply()`: after the agent loop, `actions = _parse_proposed_actions(result_text)`
then `_execute_renames(actions, ROOT_DIR)`. (Deletions stay unexecuted in S01 —
`deleted` is empty by the gate; S02 adds the executor.)
