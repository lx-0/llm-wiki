# M033-S02-T03 -- Task Plan

**Summary:** `cli.py` spawns handlers as `[sys.executable, "-m", <module>, *args]` from the chosen root (process isolation kept, `UV_PROJECT_ENVIRONMENT` / `--project` behaviour unchanged); the bash `_run_script` / `_dispatch_python` paths in `wiki` keep working byte-for-byte on the oracle (they move to Python in M034).

## Files

- Create: `scripts/core/entry.py` — the one place that knows how an engine module is
  spawned: `module_for(handler)` (`preprocessors/inbox.py` → `preprocessors.inbox`),
  `child_env()` (`scripts/` first on PYTHONPATH, the caller's PYTHONPATH kept),
  `python_m(handler, *args)` (the argv). `cli.py` (T02 pulled its `-m` spawn forward) imports
  these instead of owning them.
- Create: `tests/test_entry.py` — RED first: the three helpers; `test_cli_dispatch.py`
  re-pointed at `core.entry`.
- Modify: `scripts/core/piggybacks.py` — the runner and each task run as modules:
  `[sys.executable, "-m", "core.piggyback_runner", name, timeout, "--", sys.executable, "-m",
  module_for(cmd[0]), *cmd[1:]]` with `child_env()`; `tests/test_piggybacks.py` (asserts the
  resolved script path today → the `-m` shape).
- Modify: `scripts/flush.py` — `compile.py`, `dashboard/dashboard_stats.py`,
  `dashboard/dashboard_lint.py` spawned via `python_m`; `scripts/preprocessors/inbox.py` +
  `html_ingest.py` — their `compile.py` spawn likewise (`tests/test_flush_trigger.py` /
  `tests/test_inbox_and_html.py` if they pin the argv).
- Modify: `wiki` (two lines: `scripts/migrations/migrate_config_keys.py`,
  `scripts/migrations/migrate_log_md_path.py` by path) and `lib/seed.sh` (two lines:
  `scripts/dashboard/agent_buttons.py` by path) — `python -m migrations.migrate_config_keys`
  etc. with `PYTHONPATH="$WIKI_DIR/scripts"`, so T04 can remove those modules' bootstraps;
  the invocation changes, the command does not (M034 ports the commands).
- Not touched: `hooks/*.py` spawn `scripts/flush.py` by path — a top-level script gets
  `scripts/` as `sys.path[0]` from Python itself; `_run_script` / `_dispatch_python` in `wiki`
  run top-level scripts by path for the same reason.

## What this does

After T02 the dispatcher already runs handlers as modules; this task makes every other
engine-to-engine spawn do the same through one helper, so T04 can delete the per-module
`sys.path.insert` bootstraps knowing that nothing runs a sub-package module by file path any
more: piggybacks (runner + task), flush's compile / dashboard children, the preprocessors'
compile trigger, and the four bash lines that call sub-package scripts directly. The
behaviour oracle, the suite and three live spawns (a piggyback dry-run through
`run_due_piggybacks` with a fake clock, `wiki seed --check`, the config migration's
`--dry-run`) prove nothing changed for the operator.
