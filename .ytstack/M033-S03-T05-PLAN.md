## What this does

One JSON state seam. Every runtime state file under `.wiki/state/` that a process reads,
mutates and writes back goes through `core.state_store.StateStore`: a fresh read under the
file's exclusive flock, a mutator that touches only the keys this writer owns, an atomic
`tmp + os.replace` save — so two processes on the same file merge key-wise instead of
last-writer-wins, and a kill mid-write can never leave a torn file. The seven hand-rolled
copies of "read JSON, mutate, `write_text(json.dumps(`" are gone; a smell-based guard keeps
the next one out. Operator-visible: nothing in behaviour; each folded state file gains a
sibling `<name>.lock` under `.wiki/state/` (the seam's convention, already there for
`state.json` and the dream stores); `folder-index.json` would escape a non-ASCII root id
(none exist in the shipped config shapes; readers are unaffected).
