# M034-S06-T02 -- Task Plan

**Summary:** One output path (exit criterion 5). The command modules write their output
through `core.console` and no longer call `print` themselves. A gate refuses a `print(` call
in a command module outside an allowlist with reasons. Before: 391 calls in the catalogue's
47 handler and subroute modules. After: 0 outside the allowlist.

## Files

- Modify: `scripts/core/console.py`.
  - `say(*values, sep=" ", end="\n", file=None, flush=False)`: a command's plain output,
    stdout unless `file` names another stream.
  - Same contract as `print`, so the conversion changes no byte of output. The one seam is
    where later behaviour goes (a quiet mode, a payload-only guard).
  - The status helpers (`ok` / `warn` / `info` / `fail` / `print_error` / `banner`) stay as
    they are.
- Modify: the handler modules that call `print`: 25 of the 47, from `curiosity/cli.py` (49)
  down to `seed_cli.py` (2). Each one imports `say` and has every `print(` replaced.
  - Measured first: in each module the text `print(` occurs exactly as often as the AST
    finds `print` calls. There is no `pprint`, no `print` named in a docstring, and no
    `print` used as a value.
  - Every `file=` target is `sys.stderr`, a stream and not a data file.
- Create: `tests/test_output_seam.py`.
  - The gate: an AST walk over the catalogue's handler and subroute modules, refusing any
    `print(...)` call not in `ALLOWED` (path → reason).
  - `say`: stdout or the given stream, judged at call time (capsys, a swapped
    `sys.stderr`).
- Docs: `AGENTS.md` (conventions: output via `core/console`, `say` named), and
  `docs/engine-layout.md` (the core/console line).
- No CHANGELOG entry: no output changes, which the bash oracle and the payload goldens hold.

## What this does

The per-module change is mechanical: `print(` → `say(` plus the import. The gate makes it
stick, since a new `print(` in a command fails the suite and names the module and line.
