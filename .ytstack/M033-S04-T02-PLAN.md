## What this does

`dream_entity` reads as the phase list its docstring and comments already describe:
corpus → gate → prompt within budget → size check → dry-run → SDK → failure or success →
write verdict + backoff → low-token warning → stamp corpus → history → web-research
post-pass → outcome. Nothing a caller or a test can observe changes: the same `DreamOutcome`
fields on every path, the same log lines, the same SDK spec, the same argv surface.
