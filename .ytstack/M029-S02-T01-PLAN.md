# M029-S02-T01 -- Task Plan

**Summary:** Lifecycle backend in `desktop/` — start / stop / restart the
screenpipe listener via `launchctl`, ported from `~/.screenpipe/sp` but
**self-contained** (no runtime dependency on the prototype). The freshness probe
already lives in `status.ts` (T02) — this task is only the actions.

## Files

- Create: `desktop/src/listeners/lifecycle.ts` — `startListener` / `stopListener`
  / `restartListener(def)` over `launchctl`, reusing `isRunning` from `status.ts`.
  Pure helper `guiDomainTarget(uid, label)` separated + unit-testable.
- Create: `desktop/src/listeners/lifecycle.test.ts` — vitest for the pure helper +
  the action→launchctl-arg mapping (no live system mutation here; that's S02-T03).

## What this does

Mirror the verified `sp` logic, in TS:
- **start:** if not running → `launchctl bootstrap gui/<uid> <plistPath>` (no-op if
  already running).
- **stop:** if running → `launchctl bootout gui/<uid>/<label>` (no-op if stopped).
- **restart:** running → `launchctl kickstart -k gui/<uid>/<label>`, else bootstrap.
- All via `execFileSync('launchctl', [...])` (array args — shell-injection-safe per
  the project rule). Each returns `{ ok, action, error? }`. uid from
  `process.getuid()`.

No engine involvement (system data + system control). Keeps the app's
system-control lane (vs Obsidian's browse/edit lane).
