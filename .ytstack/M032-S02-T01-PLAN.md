# M032-S02-T01 -- Task Plan

**Summary:** Engine action catalogue + menu JSON: `scripts/core/actions.py` holds the operator-facing vocabulary (id → plain-English title singular/plural, verb, group, argv, tool flag); `menu_context.build_suggestions` keys every probe on a catalogue id and emits `id`/`title`/`verb`/`group`/`argv` (+ `label` for the TUI); `wiki menu --json` gains `schema: 2` + `tools`; `menu.py` consumes `argv`.

## Files

- Create: `scripts/core/actions.py` — `SCHEMA = 2`, `ActionSpec` (frozen dataclass: `id`, `verb`, `group`, `argv`, `title_one`, `title_many`, `tool`), `CATALOGUE` (the table), `get(id)`, `verb_for(argv)` (exact argv match, then argv[0] via `VERB_BY_COMMAND`), `tools()`, `ActionSpec.title(n)`, `ActionSpec.to_json(n)`.
- Create: `tests/test_actions.py` — titles pluralize on `{n}`, count-less titles ignore `n`, every catalogue `argv` starts with a `wiki` subcommand that exists in `cli.py`'s table or the bash dispatcher list, `verb_for` falls back by command, `tools()` carries only `tool=True` entries, ids unique.
- Modify: `scripts/menu_context.py` — probe table becomes `(action_id, probe, priority, label_fn)`; `build_suggestions` reads group/argv/verb/title from the catalogue and emits `{"id","count","label","title","verb","group","argv","priority","key"}` (no `cmd`); `main()` writes `{"schema": 2, "status", "suggestions", "tools"}`.
- Modify: `scripts/menu.py` — `HomeState.actions()` builds `dispatch_args`/`cmd_display` from `argv`.
- Modify: `tests/test_menu_context.py` — key-set assertion, `by_cmd` lookups → `by_id`, end-to-end payload keys include `schema` + `tools`.

## What this does

Principle 3 of the arc: the engine owns its vocabulary. Today `wiki menu --json` emits
operator-term `label`s plus a `cmd` string, and the desktop re-phrases both with regex/maps
(`friendlyPending`, `pendingVerb`); any new probe leaks jargon. After this task every actionable
thing the engine can suggest is a catalogue row:

```
id               verb     group   argv                                   title_one / title_many
process-inbox    Sort     do      process-inbox                          {n} new capture to sort / {n} new captures to sort
compile          Add      do      compile                                {n} new source to add / {n} new sources to add
curiosity-folder Review   review  curiosity --type folder-deep-scan      {n} document scan to review / … scans …
curiosity-email  Explore  auto    curiosity --type email-deep-scan       {n} email scan pending / … scans …
suggestions      Run      do      suggestions                            {n} approved suggestion to run / …
dream-sweep      Refresh  auto    dream --all-entities                   {n} page needs refreshing / {n} pages need refreshing
flush            Save     do      flush                                  Save today's session to your wiki
lint             Check    auto    lint --structural-only                 Notes changed since the last health check
links-fix        Fix      tools   links --fix --yes                      Fix broken links                     (tool)
dedup            Review   tools   dedup                                  Find duplicate pages                 (tool)
review-wiki      Review   tools   review-wiki                            Review page quality                  (tool)
```

`lint` and `dream-sweep` are both probe-backed and tools (one row, `tool=True`): the GUI shows the
counted suggestion when present and the bare tool otherwise, deduping by argv. The TUI keeps
`label` (operator terms, DECISIONS 2026-06-24) and derives its `→ wiki …` hint from `argv`.
`verb_for(argv)` also serves doctor checks in T02 (`setup` → Set up, `hooks` → Install,
`update` → Update, `*-auth` → Sign in, `install-shortcut` → Install, `reindex` → Rebuild,
`compile` → Add, `dream` → Refresh, `links` → Fix, `lint` → Check). Consumer grep before the
`cmd` key disappears: `grep -rn '"cmd"\|cmd_display\|\.cmd\b' scripts/ tests/ docs/ desktop/src`
— desktop consumers follow in T03/T04 (the app keeps working against the old key until then only
if it tolerates a missing `cmd`; `parseMenu` defaults it to `''`, so nothing crashes).

TDD: tests first (`test_actions.py` + the updated `test_menu_context.py` expectations), watch them
fail, then the catalogue + wiring.
