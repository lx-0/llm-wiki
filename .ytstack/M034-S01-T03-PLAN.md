## What this does

1. **Scratch engine to HEAD.** Fast-forward `/tmp/lxw-scratch/.wiki` from the local repo. It
   is scratch: the live vault is never touched, and nothing is installed under `~`.
2. **The before tree, for two command paths:**
   - `wiki collect --list`, which goes through `_dispatch_python`: read-only, no network.
     Expected: `uv` (bash exec'd into it) → `python cli.py` → `python -m collectors.cli`.
   - `wiki doctor --quick --json`, a bash wrapper (T05 ports it). Expected: bash → `uv` →
     `python doctor.py`, with bash kept as the parent because there is no `exec`.
3. **Evidence for question 1**, counted rather than recalled. These are what in-process
   dispatch would share between handlers in one interpreter:
   - handler modules that set `os.environ` at import (`CLAUDE_INVOKED_BY`, the flush SDK-env
     sanitising before the SDK import);
   - handler modules that configure logging (root handlers persist across `runpy` calls);
   - `sys.exit` calls in handler modules;
   - module-level state (`CONFIG`, ledgers) that a second handler would inherit dirty.
4. **Evidence for question 2.** The files that import the engine's top-level packages
   (`core`, `collectors`, …), and with them the hook bootstrap, `pyproject`'s pytest
   `pythonpath`, `tests/test_layout.py` and the docs. These are the touch-set of a rename.
   Weighed against the consumers: none imports the engine as a package, and all of them
   call `<vault>/.wiki/wiki`.
5. **Write the two DECISIONS entries** in the Context / Chose / Rejected / Consequences shape,
   and close questions 1 and 2 in M034-CONTEXT.
