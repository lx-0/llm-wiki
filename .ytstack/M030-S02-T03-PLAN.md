# M030-S02-T03 -- Task Plan

**Summary:** Publish executor: sequential write/retract per the plan, per-article fail-soft on tool rejects (secret gate et al.), manifest updated only on server success; CLI wired so `wiki publish` (without --dry-run) executes when `publish.enabled`.

## Files

- Create: `scripts/publish/executor.py`
- Modify: `scripts/publish/cli.py` (live path: config gate + executor + report rendering)
- Create: `tests/test_publish_executor.py`

## What this does

- `execute_publish(client, store, plan, start_payload, wiki_slug) -> PublishReport{created, updated, retracted, skipped[(slug, reason)], start_page_written, unchanged}`.
- Start page first: `needs_start_page` → `write_article(..., start_page=True)` → `record_start_page`; ToolCallError = warn + continue.
- Articles sequentially (contract: no batch): create/update via `write_article {wiki, name, description, content}` → `record_published` on success; `ToolCallError` (server reject: secret gate, cross-wiki, validation) → skipped + WARNING via module logger, run continues; `PublishClientError` (transport/auth) propagates — successes so far are already persisted, rerun resumes.
- Retractions: `delete_object {object_id: slug}` (article id = slug per contract/write_article result) → `record_retracted`; ToolCallError → skipped + warning.
- CLI: without `--dry-run` — `publish.enabled` false → actionable error exit 1; else resolve token, `ensure_wiki`, build plan, execute, print human/`--json` report.
