## What this does

The panel's three independent lists (doctor checks, menu suggestions, hardcoded advanced
commands) become one derivation. Rules, pinned by tests:

1. **Identity is argv.** `key = argv.join(' ')`; doctor checks without `dispatchArgs` are not
   actions (they stay health information for the Health tile).
2. **Dedupe by key with field precedence:** `title` + `verb` + `count` from the menu suggestion
   when present (it is the concrete, counted phrasing), else from the doctor check, else from
   the tool; `severity` is the doctor's (`critical` > `warning`) whenever a doctor check shares
   the key; `sources` records which inputs contributed (`['menu','tool']`).
3. **Order:** severity rows first (`critical`, then `warning`, stable), then menu groups
   `do` → `review` → `auto` in engine order, then tools in engine order.
4. **Run state is a pure overlay:** `withRunState` marks the row whose key equals `running` as
   `running`, rows present in `results` as `done` / `failed`, the rest `idle` — no component
   state leaks into the model.

The engine's `engine-update-available` check is filtered out upstream (`parseDoctor` already
turns it into `updateAvailable`), so it never reaches the merge. `ENGINE_COMMANDS` /
`ADVANCED_COMMANDS` in `vault/compile.ts` / `vault/ipc.ts` are retired in T04 once the tools list
arrives from the engine; this task does not touch them.
