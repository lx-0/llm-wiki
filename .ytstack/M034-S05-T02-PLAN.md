## What this does

Phase 2, in the bash's order and with its exact text (`core/console`'s `ok` / `info` / `warn`
are the bash's, to stdout):

```
after = git rev-parse --short HEAD
before == after → ok "Already up to date (<before>)"
else → ok "Updated <before> → <after>" + the two-line hooks hint (dim comment on a terminal)
info "Syncing Python dependencies (uv sync, idempotent) …"
uv sync --project <wiki> --quiet   (fails → warn "… To retry, run: <sync hint>")
if UV_PROJECT_ENVIRONMENT:            (the bootstrap exported it: cloud vault or the operator's)
    info "Engine environment: <venv> (outside cloud-synced storage)"
    .wiki/.venv a real dir → warn "stale in-vault environment … rm -rf '<path>'"
    agents.installed_wiki_commands: any command without UV_PROJECT_ENVIRONMENT=
        → warn "hooks still run the engine from the in-vault environment: claude (user), … — re-run: wiki hooks install"
info "Migrating config.yaml …" → sys.executable -m migrations.migrate_config_keys --vault <root> --apply
info "Relocating operations log …" → sys.executable -m migrations.migrate_log_md_path --vault <root>
    (children with PYTHONPATH=<wiki>/scripts; a nonzero exit → the bash's warnings)
--no-skills → info "skills: skipped (--no-skills)"; else skills_cli.sync(), any failure
    → warn "skills sync failed — rerun: wiki skills sync"
```

- **The migrations stay child processes.** Each sets up its own console logging, and an
  in-process import after `uv sync` would not see a package the sync just added.
- **The sync hint** is `UV_PROJECT_ENVIRONMENT=<quoted> uv sync --project <quoted>`. It is
  quoted by `agents.shell_quote`, the bash's `shell_quote`, so the existing paste-back test
  holds.
