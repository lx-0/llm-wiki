# M030-S02-T02 -- Task Plan

**Summary:** Wiki bootstrap: idempotent `create_wiki` (existence via `list_wikis`) with `managed_by: "llm-wiki"`, plus the generated start-page article (MOC links + counts) tracked OUTSIDE the article manifest so the delta engine never plans its retraction.

## Files

- Create: `scripts/publish/bootstrap.py`
- Create: `tests/test_publish_bootstrap.py`

## What this does

- `ensure_wiki(client, slug, name) -> bool`: `list_wikis` (result shape verified in wiki-tools.ts: `{"wikis": [...]}` as pretty-printed text content) → present: no-op/False; absent: `create_wiki {name, slug, managed_by: "llm-wiki"}` → True.
- `START_SLUG = "start"`; `start_page_payload(slug_map, wiki_name) -> ArticlePayload`: generated overview (article count + links to every `MOCs/` slug), synthetic rel `<generated:start-page>`, description fixed non-empty; raises ValueError if an operator article already claims the slug.
- `needs_start_page(store, payload) -> bool` + `record_start_page(store, payload)`: hash tracked under the manifest's separate `start_page` key — NOT `articles`, so `plan_delta` never sees it (a recorded start page in `articles` would be planned as a retraction on every run).
