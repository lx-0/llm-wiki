# M033-S05-T03 -- Task Plan

**Summary:** The contract is typed once. The `menu --json` / `doctor --json` payloads are
defined as types in one module. A committed generator writes their JSON Schemas into
`docs/contracts/`, and pytest validates the oracle's golden payloads against them.

## Files

- Create: `scripts/core/contracts.py`. It holds the schema-2 payload types as `TypedDict`s,
  defined once:
  - `ActionJSON` and `CheckJSON` move here from `core/actions` / `core/health` (T02).
  - `SuggestionJSON(ActionJSON)` adds `count`, `label`, `priority` and `key`.
  - `StatusJSON` is `total=False`, because every status probe can fail and drop its key.
  - The two envelopes are `MenuJSON` (`schema`, `status`, `suggestions`, `tools`) and
    `DoctorJSON` (`schema`, `vault`, `engine_revision`, `summary`, `checks`), plus
    `HealthSummaryJSON`.

  The module also holds a small TypedDict → JSON Schema (draft 2020-12) converter, and
  `python -m core.contracts --write | --check`, the `core.config_docs` pattern. Type mapping:
  `str` / `int` / `bool` / `X | None` / `list[X]` / `dict[str, Any]` / `Literal`, and nested
  `TypedDict`s go to `$defs`. `additionalProperties: false`, so a key the engine adds without
  the types fails validation instead of drifting past the desktop.
- Modify: `scripts/core/actions.py` and `scripts/core/health/__init__.py`. They import their
  payload types from `core.contracts`; `CheckJSON` leaves health's `__all__`.
- Modify: `scripts/menu_context.py` and `scripts/doctor.py`. The builders return the contract
  types: `build_status() -> StatusJSON`, the suggestions `list[SuggestionJSON]`, and the
  emitted envelopes `MenuJSON` / `DoctorJSON`.
- Create (generated): `docs/contracts/menu.schema.json` and `docs/contracts/doctor.schema.json`.
- Create: `tests/test_contracts.py`.
  - The committed schemas equal the generated ones (drift gate).
  - Both oracle goldens validate.
  - A golden with an unknown key, a wrong type or a missing required key does not validate
    (seen to fail).
  - Each TypedDict field reaches the schema.
- Modify: `pyproject.toml` + `uv.lock`. `jsonschema` becomes explicit in `dev`; today it is
  only a transitive dependency via the SDK, and engine deps are explicit (KNOWLEDGE).
- Modify: `docs/cli.md`, where the payloads are documented, gets a pointer to the schema files
  and to the regeneration command. `docs/engine-layout.md` gets the `contracts.py` line.

## What this does

Today the payload shapes live in three places that can drift: the dicts the engine builds,
the prose examples in `docs/cli.md`, and the desktop's hand-written interfaces in
`src/lib/actions.ts`. After this task one Python module defines them. The schema files are
generated from it and the goldens prove the engine's real output matches. T04 makes the
desktop validate against the same files.

Behaviour is unchanged: the types annotate, they do not run, and the oracle goldens stay
byte-identical. `ty check scripts/core` stays clean, including the new module. The report-only
count for all of `scripts/` must not grow, since the annotations in `menu_context` / `doctor`
are checked there too.
