## What this does

**Failure states** (one `_mark_failed(request, request_path, *, status,
error, failed_as_of_mtime)` helper, email `_mark_error` template — adds
`last_error`, `last_attempt_at`, and the staleness anchor):

| condition                     | status         | staleness anchor          |
|-------------------------------|----------------|---------------------------|
| file missing (stale index)    | `stale`        | none (file gone)          |
| provider exception / `.error` | `error`        | current file mtime        |
| NOT-ANSWERED sentinel         | `not-answered` | `answer.as_of_mtime`      |

All three return `success=False` and persist NOTHING under
`raw/notes/folder/` (unchanged from T02).

**Re-dispatch gate** (top of the real-run branch; dry-run stays
ungated — it's the preview): on a request whose status is already
terminal:

- `done` / `rejected` → skip, `RunResult(False, "already_<status>")`.
- `stale` → retry iff the file EXISTS again, else skip
  (`"still_missing"`).
- `error` / `not-answered` → retry iff the file's CURRENT mtime differs
  from the recorded `failed_as_of_mtime` (the source changed → the
  failure is invalidated), else skip
  (`"unchanged_since_failure"`) WITHOUT calling the provider.
- `pending` → normal flow.

This is the "later source change can invalidate" semantics: the failed
request carries the mtime it failed against; touching/replacing the file
makes an explicit re-dispatch (operator today, S06 scheduler later)
re-eligible, while unchanged files can never burn provider spend twice.

Tests (~5):

1. provider error → request marked `error` + `last_error` +
   `failed_as_of_mtime` == file mtime (REWRITE of T02's
   `test_provider_error_leaves_request_untouched`).
2. sentinel → request marked `not-answered` + anchor == answer's
   as_of_mtime, nothing persisted (REWRITE of T02's sentinel test's
   request-untouched assert).
3. quarantine skip: re-dispatch of an `error` request with UNCHANGED
   mtime → `unchanged_since_failure`, provider NOT constructed
   (get_provider monkeypatched to raise); after `os.utime` bump →
   provider called, success path completes.
4. `stale` retry: missing file → `stale`; re-dispatch while missing →
   `still_missing`; create the file → retry proceeds to the provider.
5. `done` re-dispatch → `already_done`, request byte-unchanged.
