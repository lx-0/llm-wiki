# M034-S03-T05 -- Task Plan

**Summary:** Port `wiki hooks install/uninstall/status` and `wiki status` to Python
(`scripts/hooks_cli.py`), at parity with the bash oracle (T02's record). They run on
`core/agents` (registry, payload, `merge`, `without_wiki_hooks`) and `core/backup`.
`setup`'s hooks step runs in-process. Release 0.7.18.

**Oracle first.** Three bash cases are recorded and pushed before the first line of port
code:
- `hooks-install-unreadable-config` — an existing config that is not JSON;
- `hooks-uninstall-unreadable-config` — the same, on uninstall;
- `hooks-status-command-outside-hooks` — a Claude permission rule naming a wiki hook
  command, with no hooks installed.

The port re-records these three, with the differences below. Every other hooks / status /
setup golden must pass unchanged. That includes the padding: bash's `%-30s` counts bytes,
so `—` takes 3 of the 30.

**Decided differences**, stated in the commit and the CHANGELOG:
1. **The probe walks the hook entries.** This applies to `hooks status`, `wiki status` and
   doctor's `hooks-installed`. A config counts as installed when an entry under its `hooks`
   block runs a wiki command, by the one grammar, as merge and uninstall decide. The same
   text elsewhere (a permission rule) does not count, a JSON-escaped command does, and
   unreadable JSON is not installed. Doctor's stale-environment warning checks the wiki's
   own commands, not the whole file.
2. **`wiki hooks --help` is corrected.** Uninstall uses the one grammar (not
   `.wiki/hooks/`), the merge no longer runs through jq, and Cursor registers
   `sessionStart` / `sessionEnd` / `preCompact`.
3. **Hooks need no `jq`.** `hooks-install-payload-fails` (a jq that cannot run) no longer
   fails and is dropped. Its replacement is `hooks-install-unreadable-config`.
4. **An unreadable config is reported with Python's parse error** instead of jq's.
5. **`wiki status <word>` is refused**, as every ported command refuses a word no route
   names. The bash ignored it.
