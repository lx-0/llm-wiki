## What this does

Adds the engine-level toggle for `compile_role` default-by-location inference. When `True` (default), `infer_compile_role()` (T01) uses LOCATION_DEFAULTS map to assign roles based on top-level segment (raw/daily/inbox/knowledge → source-only). When `False`, all files without explicit frontmatter `compile_role:` short-circuit to `source-only`.

Reason for the knob: an operator with a non-standard vault layout (custom top-level folders) might want to disable the inference and require explicit frontmatter. Default-on matches the standard vault structure shipped via `wiki seed`.

T01's `infer_compile_role()` already accepts this as a `default_by_location` keyword arg. T02 plumbs `CONFIG.limits.compile_role_default_by_location` into actual callers (added in S02-T01).

Same-commit hard-rule rationale: dataclass-default fallthrough means a NEW knob silently works in code without ever appearing in operator's `<vault>/.wiki/config.yaml`. Operator never sees that it's tunable. The migration writes the key into operator configs on `wiki update` so it shows up.
