## What this does

Each `_run_one_account` reads as its phase list. gmeet: auth → `_discover_docs` (own
folder + gemini-notes mail, unioned by Drive id) → `_group_by_meeting` → per group
`_new_stubs_for_group` → `_export_group` → `_merge_group` | `_write_group` →
`_finish_account`. calendar: auth → calendars → window → per calendar `_fetch_events` →
`_event_block` per event → the etag / watermark entry → the account state + message.
Nothing a caller, a test, the state file or the operator's logs can observe changes: the
same log lines, the same filenames, the same frontmatter, the same rollup line, the same
state keys, the same messages. Two quirks are moved verbatim, not fixed: calendar's
`time_min = acct.since` reassignment leaks into the later calendars of the same account
(carried on `_CalendarScan.time_min`), and gmeet's merge path logs `merged N Doc(s)` from
`len(exports)` even when the inner loop broke early on an unparseable post-merge
frontmatter. Both go to Follow-ups; a fix is its own commit with its own test.
