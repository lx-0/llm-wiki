# M034-S01-T02 -- Task Plan

**Summary:** Bash oracle, mutating commands. Each runs on a fresh fixture vault and a fresh
`HOME`, with its answers scripted on stdin (the bash prompts are line-based `read -r`; EOF
takes the default). What the oracle records is the **change** the command made: the files and
symlinks added, changed and removed under the vault and under `HOME`, plus its stdout,
stderr and exit code.

## Files

- Modify: `tests/_oracle.py`
  - `run_wiki(..., stdin=)`: scripted answers.
  - `tree_manifest(root, exclude)` / `manifest_diff(before, after, placeholders)`: the
    change, with small UTF-8 files in full, others as sha256 + size, symlinks with their
    target, and `.bak-<stamp>` backups named by pattern.
- Modify: `tests/test_bash_oracle.py` — a function-scoped fresh fixture per mutating case,
  and the parametrized cases below.
- Create: `tests/golden/bash/*.txt` — the mutating goldens, recorded from the bash.

## What this does

Cases. Each starts fresh, and some first run a setup step whose change is not recorded.

- **config:** `config set models.compile_model claude-sonnet-4-6`.
- **setup:** `setup` with the six wizard answers scripted (URL kept, the sonnet model, hour
  20, procmail no, local LLM default, global skill no) and the hooks prompt answered "n".
- **hooks:**
  - `hooks install` for claude at user scope (`1`, `1`, `y`);
  - `hooks install` for all four agents at project scope;
  - `hooks install` merging into a pre-existing user `settings.json` that carries another
    tool's hook and a permission;
  - `hooks uninstall` after an install.
- **skills:**
  - `skills install`, `skills sync`;
  - `skills install --global`, and `skills uninstall --global` after it.
- **seed:**
  - `seed` on the fresh vault;
  - `seed --check` and `seed --force` after one seeded file was edited;
  - `seed .obsidian/app.json --force`;
  - `seed --extract-custom .obsidian/graph.json` after a graph setting changed.
- **install-shortcut:** `install-shortcut` and `install-shortcut --print-only`. With PATH
  pinned, `~/.local/bin` is never on it, so the printed rc line is recorded too.

Excluded from the manifest: the engine copy's runtime parts and its `.git`, and
`.wiki/logs/` (timestamps only). Everything else under the vault and under `HOME` is listed:
`.wiki/config.yaml`, `.wiki/custom/`, `.wiki/state/`, the vault root and the agent configs.
