## What this does

Operations protocol on the lxw vault, in order, each step verified
before the next:

1. **`wiki update`** — pulls S03–S05 (producer, dispatch, backend,
   prompts, sensitivity; lxw last updated before those commits).
2. **Tag a root:** set `sensitivity: private` on the `private-documents`
   entry in `<vault>/.wiki/config.yaml` (verifies the T02 carry; config
   edit per the authorized lxw-configuration flow, backup to /tmp first).
3. **`wiki index --force`** — fresh digests in the current format.
4. **Obtain a real request:** prefer the real producer —
   `wiki produce folder_curiosity <recent raw source>` ($0, Ollama). If
   no gap survives the anchor/confidence gates after 2-3 sources,
   hand-seed ONE request for an operator-named file (named in chat = the
   informed consent for step 5; honest deviation note in the summary).
5. **Dispatch with consent:** preferred: operator runs
   `wiki curiosity --walk` (live-tests T05's consent card, his keypress
   IS the gate). Fallback when seeded + operator already consented in
   chat: `wiki curiosity --run <slug>`. Verify: answer artifact in
   `raw/notes/folder/` with `as_of:`/`as_of_mtime` + `sensitivity:
   private`, NO raw body (spot-check), request `done`.
6. **`wiki compile --file raw/notes/folder/answer-<slug>.md`** — one
   compile call distils it. Verify: the target `knowledge/` article
   gained the fact, carries `sensitivity: private` (T02 carry,
   empirical) and provenance (`compiled_from` includes the answer).
7. **`wiki query "<trove topic>"`** — the returned answer cites the
   folder-sourced fact. Exit criterion #6: the fact came from the
   folder, not the narrative layer.

Abort criteria: any step failing gets root-caused before proceeding
(systematic-debugging posture); no retries that double spend without a
diagnosis. All observed outputs land in the summary.
