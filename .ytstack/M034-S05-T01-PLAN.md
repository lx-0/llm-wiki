# M034-S05-T01 -- Task Plan

**Summary:** Oracle first, fix first, for `wiki update`. The bash's behaviour is recorded
before T02 ports it, from fixture vaults whose engine is a clone of a local `file://` origin
that is one commit ahead. Bash defects the recording turns up are fixed in the bash first and
then recorded, with a release when they are operator-visible (S04 found seven).

## Files

- Modify: `tests/_oracle.py`.
  - `build_update_origin(template, root)`: a clone of the engine template as the origin.
  - The fixture vault's `.wiki/` is cloned from that origin before the origin gets one more
    commit, so a pull fast-forwards. There is no reset anywhere.
- Modify: `tests/test_bash_oracle.py`.
  - The update cases are recorded with the vault effect, as the mutating cases are. Engine
    files are not an effect.
  - Placeholders name the origin path and both revisions.
- Create: `tests/test_update_tty.py` — the stash path, which needs a terminal (`confirm`
  behind `[[ -t 0 ]]`), driven through a pty:
  - a tracked engine edit is stashed, the pull runs, and the edit is re-applied cleanly;
  - an edit that would conflict with the pulled commit is left in the stash, with the
    recovery hint.
  - The transcripts are recorded as goldens.
- Create: `tests/golden/bash/update-*.txt`.
- If a defect is fixed: `wiki`, a test, `CHANGELOG.md`, `pyproject.toml`, `uv.lock`.
